# Build the core and adopt at explicit seams

No surveyed open-source project provides Health Engine's combined portable one-Subject Workspace, append-only correction and verification history, source-level provenance, structured cross-domain Analysis, and consumer-genomics behavior. Build that core as native Rust modules over the Workspace SQLite record, while adopting focused libraries, public datasets, and exchange standards only behind explicit seams where they have demonstrated value.

FHIR may become an import/export adapter but is not the canonical internal record. MCP may become an adapter over the same library interface used by the CLI, but the versioned JSON CLI remains sufficient for initial agent integration. Fasten Health, openEHR, PharmCAT, Open-CRAVAT, CQL implementations, and Open mHealth are references, conformance oracles, or optional future integrations rather than required runtimes. The append-only domain model does not imply a generic event store or materialized-view architecture, and the initial rules implementation does not imply a generic DAG or embedded WASM runtime. Full UMLS/RxNorm/SNOMED acquisition is deferred until a concrete normalization or interoperability requirement justifies its licensing and credential burden.
